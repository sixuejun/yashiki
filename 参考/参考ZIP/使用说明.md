### 1.3 区域与实体的关系

- **区域（regions）** 是几何事实：哪些地方能走、哪些地方会挡住角色、哪些地方要淡出前景。
- **实体（entities）** 是「这个位置上有个什么东西」：出生点、传送阵、宝箱、怪物、灯、门。
- 两者**互不相关**：实体不参与切片、不参与渲染顺序、不参与遮挡判定。

## 二、坐标与判定约定（最重要）

这一节写错，运行器里所有「走不过去 / 站不住 / 被挡住」的问题都会出在这里。

### 2.1 角色位置 = 脚底锚点

角色的世界坐标 `(x, y)` 是**脚底着地的那一点**，不是立绘中心，也不是外框左上角。

立绘外框由锚点反推：

```text
外框左上角.x = 角色.x - sprite.width  * anchor.x
外框左上角.y = 角色.y - sprite.height * anchor.y
```

本地图的 `actor` 段：

```json
{
  "anchor":         { "x": 0.33, "y": 0.77 },
  "sprite":         { "width": 36, "height": 56 },
  "collision_box":  { "width": 26, "height": 9 },
  "ghost_alpha":    0.35,
  "collision_test": "aabb-overlap",
  "occlusion_test": "foot-box-overlap"
}
```

> ⚠ `anchor` 是 **(0.33, 0.77)**，不是 (0.5, 1) ——
> 意思是立绘的**脚底偏左下**，不是外框的正下方。
> 照抄这个值，不要想当然地当成 (0.5, 1)。

### 2.2 碰撞只看脚底盒，绝不能用立绘

判定用的盒子是 `collision_box`（本地图 **26 × 9** 像素），以脚底锚点**为中心**：

```text
碰撞盒 = {
  x: 角色.x - collision_box.width  / 2,     // 角色.x - 13
  y: 角色.y - collision_box.height / 2,     // 角色.y - 4.5
  w: collision_box.width,                   // 26
  h: collision_box.height,                  // 9
}
```

**禁止**用 `sprite`（36 × 56）去撞区域。立绘比脚底盒大得多，
密集红区下角色会一步都走不动 —— 这是本项目明确要避开的错误。

### 2.3 两种判定，用同一个盒子

| 判定 | 方式 | 后果 |
| --- | --- | --- |
| 碰撞（不可通行） | 脚底盒 ∩ `collision` 区域 ≠ ∅ | 有重叠就绝对不能站在那 |
| 遮挡（降层） | 脚底盒 ∩ `occlusion` 区域 ≠ ∅ | 角色降到黑层后面，并画半透明副本 |

- `occlusion` **只影响绘制层级，不阻止移动**。
- 实体（怪物、宝箱等）判断「站不站得住」时，用**同一个脚底盒**去撞 `collision` 区域。
- 实体可以有自己的脚底盒尺寸（字段 `boxW` / `boxH`），本地图**全部缺省** → 用角色的 26 × 9。

### 2.4 区域优先级

同一像素被多个区域覆盖时：

1. 先比 `priority`（数值大者优先）。本地图所有区域 `priority` 都是 `0`。
2. `priority` 相同则按 `rules.type_tiebreak` 顺序，**后者胜**：
   `collision > adjust > occlusion > top`

## 三、几何判定算法

本节给出可直接照抄的实现。运行时**只有这一份判定逻辑**，
碰撞、遮挡、寻路、实体站位全部复用它 —— 不要在不同地方写不同的判定，
否则会出现「寻路说能走，走过去却卡住」。

### 3.1 区域的外接矩形

```ts
function rectOfRegion(r: Region): Bounds {
  if (r.shape === 'rect') {
    const a = r.points[0], b = r.points[1]
    return {
      x: Math.min(a.x, b.x), y: Math.min(a.y, b.y),
      w: Math.abs(a.x - b.x), h: Math.abs(a.y - b.y),
    }
  }
  // 多边形：所有顶点的包围盒
  let x1 = Infinity, y1 = Infinity, x2 = -Infinity, y2 = -Infinity
  for (const p of r.points) {
    x1 = Math.min(x1, p.x); y1 = Math.min(y1, p.y)
    x2 = Math.max(x2, p.x); y2 = Math.max(y2, p.y)
  }
  return { x: x1, y: y1, w: x2 - x1, h: y2 - y1 }
}
```

> 矩形区域在 `map.json` 里存的是**两个点**（左上 / 右下），
> 但两个点的顺序不保证，读进来时按 `min` / `max` 归一化。

### 3.2 点是否在多边形内（射线法）

```ts
function pointInPoly(px: number, py: number, pts: Point[]): boolean {
  let inside = false
  for (let i = 0, j = pts.length - 1; i < pts.length; j = i++) {
    const xi = pts[i].x, yi = pts[i].y
    const xj = pts[j].x, yj = pts[j].y
    if ((yi > py) !== (yj > py) &&
        px < ((xj - xi) * (py - yi)) / (yj - yi) + xi) {
      inside = !inside
    }
  }
  return inside
}
```

### 3.3 区域与矩形是否相交

这是**判定站不站得住的唯一函数**。

```ts
function regionHitRect(r: Region, rect: Bounds): boolean {
  // 矩形区域：AABB 相交
  if (r.shape === 'rect') {
    const b = rectOfRegion(r)
    return !(rect.x + rect.w <= b.x || rect.x >= b.x + b.w ||
             rect.y + rect.h <= b.y || rect.y >= b.y + b.h)
  }

  // 多边形区域：三种情况任一成立即相交，缺一不可
  const p = r.points
  const corners: Point[] = [
    { x: rect.x,             y: rect.y },
    { x: rect.x + rect.w,   y: rect.y },
    { x: rect.x + rect.w,   y: rect.y + rect.h },
    { x: rect.x,             y: rect.y + rect.h },
  ]
  // ① 矩形的角点落在多边形内
  for (const c of corners) if (pointInPoly(c.x, c.y, p)) return true
  // ② 多边形的顶点落在矩形内
  for (const v of p) {
    if (v.x >= rect.x && v.x <= rect.x + rect.w &&
        v.y >= rect.y && v.y <= rect.y + rect.h) return true
  }
  // ③ 多边形的边与矩形的边相交
  for (let i = 0; i < p.length; i++) {
    const a = p[i], b = p[(i + 1) % p.length]
    for (let k = 0; k < 4; k++) {
      if (segHit(a, b, corners[k], corners[(k + 1) % 4])) return true
    }
  }
  return false
}
```

`segHit`（线段相交，叉积法）：

```ts
function cross(o: Point, a: Point, b: Point): number {
  return (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x)
}
function segHit(a: Point, b: Point, c: Point, d: Point): boolean {
  const d1 = cross(c, d, a), d2 = cross(c, d, b)
  const d3 = cross(a, b, c), d4 = cross(a, b, d)
  return ((d1 > 0 && d2 < 0) || (d1 < 0 && d2 > 0)) &&
         ((d3 > 0 && d4 < 0) || (d3 < 0 && d4 > 0))
}
```

> **多边形判定是保守近似**（斜墙会多挡一点），这是**有意为之**：
> 宁可判窄一点，也不要让角色卡进斜墙。运行器应当复刻同样的保守度。

> ⚠ 本地图的 `collision` 区域里有 **3 个是多边形**（`shape: "poly"`），
> 其余 97 个是矩形。**两种形状都要处理**，不能只写矩形判定。

### 3.4 站不站得住

```ts
/** 返回所有压住该位置的 collision 区域（空数组 = 站得住） */
function overlappingRegions(regions: Region[], x: number, y: number, bw: number, bh: number): Region[] {
  const rect = { x: x - bw / 2, y: y - bh / 2, w: bw, h: bh }
  return regions.filter(r => r.type === 'collision' && regionHitRect(r, rect))
}

function canStandAt(regions, x, y, bw = 26, bh = 9): boolean {
  // 先判越界
  if (x - bw / 2 < 0 || y - bh / 2 < 0 ||
      x + bw / 2 > CANVAS_W || y + bh / 2 > CANVAS_H) return false
  return overlappingRegions(regions, x, y, bw, bh).length === 0
}
```

### 3.5 命中遮挡区

```ts
/** 返回当前压住角色的那个 occlusion 区域（null = 没进遮挡区） */
function hitOcclusion(regions: Region[], x, y, bw, bh): Region | null {
  const rect = { x: x - bw / 2, y: y - bh / 2, w: bw, h: bh }
  // 按 priority 降序找第一个命中的（priority 相同时按 type_tiebreak，后者胜）
  const sorted = [...regions].sort((a, b) =>
    (a.priority - b.priority) || (TYPE_RANK[a.type] - TYPE_RANK[b.type]))
  for (const r of sorted) {
    if (r.type !== 'occlusion') continue
    if (regionHitRect(r, rect)) return r
  }
  return null
}
```

`TYPE_RANK`（同优先级时的类型裁决顺序，数字大的优先）：

```ts
const TYPE_RANK = { collision: 0, adjust: 1, occlusion: 2, top: 3, fade: 4 }
```

> `fade` 不参与像素裁决（它只改前景层透明度），固定排末位。

## 四、绘制顺序与图层切片

### 4.1 八步绘制顺序

`map.json` 的 `render_order` 段就是渲染的唯一依据：

```text
1. background_below    白层留在角色下方的部分
2. objects_lower       黑层被开洞落到角色下方的部分
3. character           正常角色（完整、不透明）
4. background_above    白层被紫区提到角色上方的部分（成为遮挡物）
5. objects_upper       黑层盖住角色的部分
6. character_ghost     半透明副本（ghost_alpha = 0.35）
7. foreground          前景层
8. top                 绿色最上层
```

### 4.2 白层与黑层的切片规则

这是最容易做错的部分。**白层和黑层走同一套机制**，
区别只在「默认谁在角色上方」：

**黑层（objects）**

- 默认整层在角色**上方**。
- `adjust`（黄色）区域在黑层上**开洞**：洞内的黑层像素落到 `objects_lower`，
  角色在该范围内完整可见、不叠副本。
- 没有黄色区时 `objects_lower` 全透明、`objects_upper` 是整层
  —— 即「黑层完整遮挡角色」。

**白层（background）**

- 默认整层在角色**下方**（场景图本来就在角色身后）。
- 命中一个 `target` 覆盖白层的 `occlusion` 区域时，该紫区**内部**的白层像素
  **额外**画到角色上方（`background_above`）成为遮挡物。
- 紫区外部的白层照旧留在下方。
- ⚠ 紫区内部的白层**同时保留在下方那一份** —— 场景不能因为角色挡住了就缺一块
  （否则地上会露出一个洞）。

**绿色最上层（top）**

- 只取该区域 `target` 指定的那一层：
  `background` 取白层、`objects` 取黑层、`both` 两层都取。
- 提到最顶的像素**不在** `below` / `above` 里出现 —— 同一像素只出现在一段里，
  否则角色会被挡两次。

### 4.3 切片怎么做

用 Canvas 2D 的**蒙版合成**实现。核心是三个操作：

```text
层 ∩ 蒙版   = 把层画到画布上，globalCompositeOperation = 'destination-in'
层 − 蒙版   = 把层画到画布上，globalCompositeOperation = 'destination-out'
蒙版 ∪ 蒙版 = 两个蒙版用 'source-over' 依次画上（白色填充 = 在区域内）
```

蒙版的生成：把所有相关区域的形状用**白色填充**画进一张与画布同尺寸的离屏画布。
形状用 `ctx.rect()`（矩形区域）或 `ctx.moveTo/lineTo/closePath`（多边形区域）。

具体步骤（每层独立做一次）：

```text
topMask   = 所有 target 覆盖本层的 top 区域      的并集蒙版
holeMask  = 所有 target 覆盖本层的 adjust 区域    的并集蒙版
occMask   = 当前命中的那个 occlusion 区域（仅当它的 target 覆盖本层时）= 单个蒙版

full  = 本层 − topMask           // 提到最顶的像素挖掉，不在下面出现
top   = 本层 ∩ topMask           // 最顶层

白层：
  若有 occMask：
    occInterior = occMask − topMask
    above = 本层 ∩ occInterior   // 紫区内的白层提到角色上方
    below = full    − occInterior  // 紫区内的白层 ALSO 留在下面
  否则：
    below = full
    above = 空

黑层：
  holeNoTop = holeMask − topMask
  below = 本层 ∩ holeNoTop       // 黄区内的物件落到角色下方
  above = full    − holeNoTop    // 黄区外的物件盖住角色
```

> ⚠ **关键**：即使没有任何 `adjust` 区域，蒙版也必须是一张**全透明**的画布，
> 不能跳过这步 —— 否则下片/上片会被整体跳过，
> 造成「紫色区域内没有黄色区域时该层整个消失」这种错误。

### 4.4 最顶层的合成

`top` 段要把白层和黑层的 top 内容**合成到同一张画布**再画一次：

```text
for 每层 in [background, objects]:
    该层自己的蒙版 = target 覆盖该层的 top 区域
    该层内容 = 本层 ∩ 该层蒙版
    以该层自己的 opacity 画进合成画布

最后把合成画布按 opacity = 1 画到最顶
```

> ⚠ 两层的 opacity 是**独立设置**的，所以要**分别**按各自 opacity 合成，
> 合成完不能再统一套一个 opacity（会算错）。

### 4.5 本地图的实际用量

| 类型 | 数量 | 作用目标 |
| --- | --- | --- |
| `collision` 碰撞层 | 100 | 98 作用白层，2 作用黑层 |
| `fade` 前景淡化区 | 12 | 固定前景层 |
| `occlusion` 遮挡层 | 17 | 15 作用黑层，2 作用白层 |
| `adjust` 调节层 | 3 | 1 作用两者，2 作用黑层 |

> 本地图**没有 `top` 区域**，所以第 8 步（`top`）实际为空。
> 但运行器**仍应实现这一步** —— 后续地图里加了绿色区域就不需要改运行器。

> **关于「未进入遮挡区」时的渲染**：本地图有 3 个 `adjust` 区域，
> 建议**始终按上面的八步 + 切片规则渲染**（不要在未遮挡时直接画整层黑层）。
> 统一走切片，行为才与 `render_order` 严格一致，也不会出现
> 「走进黄区前后画面突变」的怪问题。

## 五、前景淡化（fade）

本地图有 **12 个淡化区**，全部是矩形，`fadeAlpha = 0.35`，`fadePad = 4`，`clip = null`。

### 5.1 触发与迟滞

- 判定只看**脚底碰撞盒**（26 × 9），与立绘无关。
- **迟滞（防边界抖动）**：
  - 进入判定用「框向外扩张 `fadePad`（4px）」后的形状 → **提前**进入；
  - 退出判定用**原始框** → **延后**退出。
  - 于是离开要比进入多走 4 像素，形成滞回带，
    角色站在框边缘时前景不会疯狂闪烁。
- ⚠ 命中状态必须**跨帧持久化**（用一个 `Set` 存区域 id）。
  每帧重新判定而不带迟滞，角色站在框边缘时前景会闪。

```ts
const activeFade = new Set<string>()   // 帧间持久化，不进存档

/** 包围盒向外扩张 pad */
function expandBounds(b: Bounds, pad: number): Bounds {
  if (pad <= 0) return b
  return { x: b.x - pad, y: b.y - pad, w: b.w + pad * 2, h: b.h + pad * 2 }
}

/** 把包围盒包成一个「矩形区域」，好复用 regionHitRect */
function asRect(b: Bounds): Region {
  return { shape: 'rect', points: [{ x: b.x, y: b.y }, { x: b.x + b.w, y: b.y + b.h }] } as Region
}

function updateFadeTargets(regions: Region[], x, y, bw, bh): Region[] {
  const foot = { x: x - bw/2, y: y - bh/2, w: bw, h: bh }
  const out: Region[] = []
  for (const r of regions) {
    if (r.type !== 'fade') continue
    // fadePad 只对矩形生效，多边形恒为 0
    const pad = r.shape === 'rect' ? (r.fadePad ?? 4) : 0
    const padded = pad > 0 ? expandBounds(rectOfRegion(r), pad) : rectOfRegion(r)
    if (regionHitRect(asRect(padded), foot)) {
      activeFade.add(r.id)              // 提前进入
    } else if (activeFade.has(r.id) && !regionHitRect(r, foot)) {
      activeFade.delete(r.id)           // 完全走出原始框才退出
    }
    if (activeFade.has(r.id)) out.push(r)
  }
  // 清理已删除区域的残留
  const live = new Set(out.map(r => r.id))
  for (const id of [...activeFade]) if (!live.has(id)) activeFade.delete(id)
  return out
}
```

> `fadePad` **只对矩形生效**，多边形恒为 0。

### 5.2 淡出计算

`fadeAlpha` 存的是**保留**多少不透明度，淡化时用的是它的补数：

```text
globalAlpha = 1 - fadeAlpha      // 0.35 → 0.65
composite    = destination-out
```

验算：`destination-out` 的公式是 `αr = αd × (1 - αs)`，
所以 `fadeAlpha = 0` → `globalAlpha = 1` → 完全消失；
`fadeAlpha = 0.15` → `globalAlpha = 0.85` → 留 15% 轮廓。

**淡出边界**：

- `clip` 缺省为 `null` 时 → 用区域自身的 `points` 作为淡出边界。
- `clip` 非 null 时 → 用 `clip.points`（可以与触发框形状不同）。
- 淡出边界是**形状**，不是矩形包围盒：矩形区域用矩形，多边形区域用多边形路径。

### 5.3 三个硬规则

1. 角色**不降层、不出现副本**。淡化只改前景层的 alpha，黑层上下片行为完全不变。
2. 框是**触发框，不是抠图轮廓** —— 框应该比前景图里的物件画得大一圈。
   框里没画图的地方是透明像素，淡化它们等于什么都没做。
3. 判定与黑层切片（黄色区域）**毫无关系**。

## 七、角色移动

移动逻辑有四个具体的坑，**必须全部处理**，否则会出现「编辑器里能走、游戏里卡住」。

### 7.1 四个坑

1. **单步跳跃**：一帧走 5px，若前方 3px 处有墙，整步都会被否掉，
   角色会「贴着墙抖」却再也前进不了。
   → 位移拆成 **≤ 1px 的子步**逐步推进。
2. **卡在缝里**：被挤进两框之间的窄缝时，两侧都会挡住整步。
   → **拆轴处理**（x / y 分开判定），能走哪轴走哪轴（即沿墙滑动）。
3. **斜向卡死**：同时给 x 和 y 时，两轴互相否决导致原地不动。
   → 拆轴后自然解决。
4. **踩在红区里彻底卡死**：起点已经压在红区上时，任何目标位置都仍然压在红区上，
   于是每一步都被否 → 角色被**永久锁死**，四面八方都出不来。
   → **脱困规则**（见 7.2）。

另外：**越界判定独立于碰撞判定**。脚底盒超出画布即为非法，
且越界位置没有「往里蹭」的余地，一律拒绝。

### 7.2 移动实现

```ts
/** 脚底盒到「完全脱离某个红区」还差多少像素（四方向取最小值） */
function exitDistance(rect: Bounds, reg: Region): number {
  const b = rectOfRegion(reg)
  const up    = (rect.y + rect.h) - b.y
  const down  = (b.y + b.h) - rect.y
  const left  = (rect.x + rect.w) - b.x
  const right = (b.x + b.w) - rect.x
  return Math.max(0, Math.min(up, down, left, right))
}

/**
 * 脱困判定：当前踩在红区里时，候选位置是否算「在往外走」。
 * 三个条件同时满足才允许移动：
 *   1. 候选位置完全不压任何红区 → 直接放行（已经脱困）
 *   2. 候选位置压到的红区必须是当前就压着的那些（不能顺手钻进新的红区）
 *   3. 对每一个仍然压着的红区，脚底盒到「完全脱离它」的距离必须严格变小
 */
function canEscape(curOverlaps, curRect, candOverlaps, candRect): boolean {
  if (!candOverlaps.length) return true
  for (const cand of candOverlaps) {
    const cur = curOverlaps.find(r => r.id === cand.id)
    if (!cur) return false                                  // 钻进新红区 → 不许
    if (exitDistance(candRect, cand) >= exitDistance(curRect, cur)) return false  // 没更靠近 → 不许
  }
  return true
}

/** 脚底碰撞盒在 (x, y) 处的矩形 */
function footRectAt(state: { x: number, y: number }, bw: number, bh: number): Bounds {
  return { x: state.x - bw / 2, y: state.y - bh / 2, w: bw, h: bh }
}

/** 把角色脚底锚点钳制到画布内（按碰撞箱留边，立绘允许超出画布） */
function clampChar(state: { x: number, y: number }, bw: number, bh: number): void {
  const hw = Math.max(1, bw) / 2
  const hh = Math.max(1, bh) / 2
  state.x = Math.min(Math.max(state.x, hw), CANVAS_W - hw)
  state.y = Math.min(Math.max(state.y, hh), CANVAS_H - hh)
}

function tryMoveChar(state, dx, dy): boolean {
  const MAX_SUB = 1   // 子步粒度：1 像素
  const bw = state.boxW ?? 26
  const bh = state.boxH ?? 9

  // 先把可能越界的锚点拉回合法范围
  // （画布尺寸被改小、碰撞箱被调大时角色可能已越界，
  //   不先归位的话后续每个子步都会被越界判定挡住，角色彻底动不了）
  clampChar(state, bw, bh)

  const outOfBounds = (x, y) =>
    x - bw/2 < 0 || y - bh/2 < 0 || x + bw/2 > CANVAS_W || y + bh/2 > CANVAS_H

  const moveAxis = (axis: 'x'|'y') => {
    const d = axis === 'x' ? dx : dy
    if (!d) return false
    const steps = Math.max(1, Math.ceil(Math.abs(d) / MAX_SUB))
    const inc = d / steps
    let moved = false
    for (let i = 0; i < steps; i++) {
      const nx = axis === 'x' ? state.x + inc : state.x
      const ny = axis === 'y' ? state.y + inc : state.y
      if (outOfBounds(nx, ny)) break

      // ⚠ 每个子步都重新读取「当前踩在哪些红区里」，不能只在函数入口算一次。
      //   脱困过程中一旦完全离开红区，下一个子步必须立刻切回严格判定；
      //   否则会继续用宽松的脱困规则一路往墙里走（实测能穿进墙内 100px 以上）。
      const curOverlaps  = overlappingRegions(state.regions, state.x, state.y, bw, bh)
      const candOverlaps = overlappingRegions(state.regions, nx, ny, bw, bh)

      if (curOverlaps.length > 0) {
        // 脱困模式：只允许「更靠近脱离红区」的方向
        if (!canEscape(curOverlaps, footRectAt(state, bw, bh),
                       candOverlaps, footRectAt({ x: nx, y: ny }, bw, bh))) break
      } else if (candOverlaps.length > 0) {
        // 起点合法：红区一步都进不去
        break
      }

      state.x = nx
      state.y = ny
      moved = true
    }
    return moved
  }

  const movedX = moveAxis('x')
  const movedY = moveAxis('y')
  return movedX || movedY
}
```

> **从合法位置出发时规则不变 —— 红区绝对进不去。**
> 脱困规则只在「起点本来就压在红区上」时才放宽。

## 八、连通性

判断「这个房间玩家进得去吗」用洪水填充。

- 栅格边长 `cell = 2px`（见 9.1）。
- **四邻接**（上下左右），**不是八邻接** —— 八邻接会让角色「斜着穿过墙缝」，
  与实际移动的分轴 + 子步推进不符。
- 从 A 点洪水填充，检查 B 点是否被填到。

```ts
interface NavGrid {
  cell: number
  cols: number
  rows: number
  passable: Uint8Array      // 1 = 可通行
}

function flood(grid: NavGrid, startCx: number, startCy: number): Uint8Array {
  const { cols, rows, passable } = grid
  const seen = new Uint8Array(cols * rows)
  if (startCx < 0 || startCy < 0 || startCx >= cols || startCy >= rows) return seen
  if (!passable[startCy * cols + startCx]) return seen

  const stack = [startCy * cols + startCx]
  seen[stack[0]] = 1
  while (stack.length) {
    const cur = stack.pop()!
    const cx = cur % cols
    const cy = (cur - cx) / cols
    const neigh = [[cx - 1, cy], [cx + 1, cy], [cx, cy - 1], [cx, cy + 1]]
    for (const [nx, ny] of neigh) {
      if (nx < 0 || ny < 0 || nx >= cols || ny >= rows) continue
      const ni = ny * cols + nx
      if (seen[ni] || !passable[ni]) continue
      seen[ni] = 1
      stack.push(ni)
    }
  }
  return seen
}

function connected(grid: NavGrid, a: Point, b: Point): boolean {
  const s = nearestPassable(grid, a.x, a.y)
  const t = nearestPassable(grid, b.x, b.y)
  if (!s || !t) return false
  if (s.cx === t.cx && s.cy === t.cy) return true
  const seen = flood(grid, s.cx, s.cy)
  return !!seen[t.cy * grid.cols + t.cx]
}
```

> **性能提示**：`flood` 要扫整张网格（本地图 39 万格），一次约 20ms。
> 判断多个点是否互相连通时，起点相同的可以**复用同一份填充结果**
> —— 否则每查一个点就重扫一次，实体一多就明显卡顿。

## 九、寻路

### 9.1 栅格化

```text
cell = 2                                // 基准 2px，远小于 26px 的脚底盒
while (ceil(W/cell) * ceil(H/cell) > 2_000_000) cell *= 2   // 按面积封顶
cols = ceil(W / cell)
rows = ceil(H / cell)
passable = 全部可通行
```

本地图：cell = 2，768 × 512 格。

**为什么是 2px**：格子边长按整个脚底盒宽取时，采样点容易正好落在墙沿上，
一条明明能挤过去的走廊会被误判成封死。2px 远小于 26px 的脚底盒，窄门窄道不会被漏判。

**辅助函数**（找最近的可通行格子，A* 的起点/终点都要用）：

```ts
function nearestPassable(grid, x, y): { cx: number, cy: number } | null {
  const { cell, cols, rows, passable } = grid
  const idx = (cx, cy) => cy * cols + cx
  const cx = Math.floor(x / cell), cy = Math.floor(y / cell)
  if (cx >= 0 && cy >= 0 && cx < cols && cy < rows && passable[idx(cx, cy)]) {
    return { cx, cy }
  }
  // 在 3 圈邻域里找最近的
  let best = null, bestD = Infinity
  for (let r = 1; r <= 3; r++) {
    for (let dy = -r; dy <= r; dy++) {
      for (let dx = -r; dx <= r; dx++) {
        if (Math.max(Math.abs(dx), Math.abs(dy)) !== r) continue
        const nx = cx + dx, ny = cy + dy
        if (nx < 0 || ny < 0 || nx >= cols || ny >= rows) continue
        if (!passable[idx(nx, ny)]) continue
        const c = { x: nx * cell + cell / 2, y: ny * cell + cell / 2 }
        const d = Math.hypot(c.x - x, c.y - y)
        if (d < bestD) { bestD = d; best = { cx: nx, cy: ny } }
      }
    }
    if (best) return best
  }
  return best
}
```

**标记阻挡格子**：

*矩形墙*（走「膨胀矩形」，是**精确**等价而非近似）：

```text
脚底盒与矩形墙相交  ⟺  格子中心落在「墙向外扩半个盒」的矩形内
x0 = 墙.x - bw/2,  x1 = 墙.x + 墙.w + bw/2
y0 = 墙.y - bh/2,  y1 = 墙.y + 墙.h + bh/2
格子中心 (cx,cy) 严格落在 (x0,x1) × (y0,y1) 开区间内 → 阻挡
```

代价只跟墙的面积成正比，跟画布大小无关。

*多边形墙*（必须**逐格判定**，只扫它自己的包围盒）：

```text
对包围盒内的每个格子中心 p：
  box = { x: p.x - bw/2, y: p.y - bh/2, w: bw, h: bh }
  若 regionHitRect(多边形, box) → 阻挡
```

*越界*：脚底盒超出画布的格子不可通行。只扫画布边框一圈即可。

**栅格化实现**：

```ts
function buildGrid(regions: Region[], bw: number, bh: number, W = CANVAS_W, H = CANVAS_H): NavGrid {
  const hw = bw / 2, hh = bh / 2

  // 格子边长：基准 2px，再按画布面积封顶
  let cell = 2
  while (Math.ceil(W / cell) * Math.ceil(H / cell) > 2_000_000) cell *= 2
  const cols = Math.max(1, Math.ceil(W / cell))
  const rows = Math.max(1, Math.ceil(H / cell))
  const passable = new Uint8Array(cols * rows).fill(1)

  const block = (cx: number, cy: number) => {
    if (cx < 0 || cy < 0 || cx >= cols || cy >= rows) return
    passable[cy * cols + cx] = 0
  }
  const center = (cx: number, cy: number) => ({ x: cx * cell + cell / 2, y: cy * cell + cell / 2 })

  for (const reg of regions) {
    if (reg.type !== 'collision') continue

    if (reg.shape === 'rect') {
      // 膨胀后的矩形：格子中心落在这个开区间内即被挡（精确等价）
      const b = rectOfRegion(reg)
      const x0 = b.x - hw, x1 = b.x + b.w + hw
      const y0 = b.y - hh, y1 = b.y + b.h + hh
      const c0 = Math.max(0, Math.floor(x0 / cell))
      const c1 = Math.min(cols - 1, Math.ceil(x1 / cell))
      const r0 = Math.max(0, Math.floor(y0 / cell))
      const r1 = Math.min(rows - 1, Math.ceil(y1 / cell))
      for (let cy = r0; cy <= r1; cy++) {
        const c = center(0, cy)
        if (c.y <= y0 || c.y >= y1) continue
        for (let cx = c0; cx <= c1; cx++) {
          const p = center(cx, cy)
          if (p.x > x0 && p.x < x1) block(cx, cy)
        }
      }
    } else {
      // 多边形：逐格判定，只扫自己的包围盒
      const b = rectOfRegion(reg)
      const c0 = Math.max(0, Math.floor((b.x - hw) / cell))
      const c1 = Math.min(cols - 1, Math.ceil((b.x + b.w + hw) / cell))
      const r0 = Math.max(0, Math.floor((b.y - hh) / cell))
      const r1 = Math.min(rows - 1, Math.ceil((b.y + b.h + hh) / cell))
      for (let cy = r0; cy <= r1; cy++) {
        const c = center(0, cy)
        if (c.y + hh <= b.y || c.y - hh >= b.y + b.h) continue
        for (let cx = c0; cx <= c1; cx++) {
          const p = center(cx, cy)
          if (p.x + hw <= b.x || p.x - hw >= b.x + b.w) continue
          const box = { x: p.x - hw, y: p.y - hh, w: bw, h: hh * 2 }
          if (regionHitRect(reg, box)) block(cx, cy)
        }
      }
    }
  }

  // 越界的格子不可通行（只扫边框一圈）
  const frame = Math.ceil(Math.max(bw, bh) / 2 / cell) + 1
  for (let cy = 0; cy < rows; cy++) {
    for (let cx = 0; cx < cols; cx++) {
      if (cx >= frame && cx < cols - frame && cy >= frame && cy < rows - frame) continue
      const c = center(cx, cy)
      if (c.x - hw < 0 || c.y - hh < 0 || c.x + hw > W || c.y + hh > H) block(cx, cy)
    }
  }

  return { cell, cols, rows, passable }
}
```

### 9.2 A* 寻路

**小顶堆**（按 f 值排序，A* 要用）：

```ts
class MinHeap {
  private a: { f: number, i: number }[] = []
  get size() { return this.a.length }

  push(item: { f: number, i: number }) {
    const a = this.a
    a.push(item)
    let k = a.length - 1
    while (k > 0) {
      const parent = (k - 1) >> 1
      if (a[parent].f <= a[k].f) break
      const t = a[parent]; a[parent] = a[k]; a[k] = t
      k = parent
    }
  }

  pop(): { f: number, i: number } | undefined {
    const a = this.a
    if (!a.length) return undefined
    const top = a[0]
    const last = a.pop()!
    if (a.length) {
      a[0] = last
      let k = 0
      for (;;) {
        const l = k * 2 + 1, r = l + 1
        let m = k
        if (l < a.length && a[l].f < a[m].f) m = l
        if (r < a.length && a[r].f < a[m].f) m = r
        if (m === k) break
        const t = a[m]; a[m] = a[k]; a[k] = t
        k = m
      }
    }
    return top
  }
}
```

**寻路本体**：

- **八方向**，允许斜走，但**不切角**：斜走时两边正交的格子也得可通行
  （否则会从墙角斜穿过去）。
- 代价：直线步 = `cell`，斜步 = `cell × √2`。
- 启发函数（可采纳，不会高估实际距离）：

```ts
const h = (i) => {
  const cx = i % cols, cy = (i - cx) / cols
  const dx = Math.abs(cx - goalCx), dy = Math.abs(cy - goalCy)
  return (Math.max(dx, dy) + (Math.SQRT2 - 1) * Math.min(dx, dy)) * cell
}
```

- ⚠ **f 值变小时必须重新入堆**。堆序靠 f 维持，若只改 gScore/fScore 不入堆，
  这个节点会以旧的（更大的）f 被弹出，导致它被过早标记成「已关闭」，
  通往目标的路径就此丢失。
- 起点或终点不可通行时，在其 3 圈邻域内找最近的可通行格子代替。

完整骨架：

```ts
function findPath(grid, from: Point, to: Point): Point[] {
  const { cell, cols, rows, passable } = grid
  const idx = (cx, cy) => cy * cols + cx
  const center = (cx, cy) => ({ x: cx * cell + cell / 2, y: cy * cell + cell / 2 })

  const s = nearestPassable(grid, from.x, from.y)
  const t = nearestPassable(grid, to.x, to.y)
  if (!s || !t) return []

  const n = cols * rows
  const gScore = new Float64Array(n).fill(Infinity)
  const fScore = new Float64Array(n).fill(Infinity)
  const cameFrom = new Int32Array(n).fill(-1)
  const closed = new Uint8Array(n)

  const goal = idx(t.cx, t.cy)
  const h = (i) => {
    const cx = i % cols, cy = (i - cx) / cols
    const dx = Math.abs(cx - t.cx), dy = Math.abs(cy - t.cy)
    return (Math.max(dx, dy) + (Math.SQRT2 - 1) * Math.min(dx, dy)) * cell
  }

  const start = idx(s.cx, s.cy)
  gScore[start] = 0
  fScore[start] = h(start)
  const open = new MinHeap()          // 按 f 排序的小顶堆
  open.push({ f: fScore[start], i: start })

  while (open.size) {
    const cur = open.pop()
    const ci = cur.i
    if (ci === goal) break
    if (closed[ci]) continue
    closed[ci] = 1

    const cx = ci % cols, cy = (ci - cx) / cols
    for (let dy = -1; dy <= 1; dy++) {
      for (let dx = -1; dx <= 1; dx++) {
        if (dx === 0 && dy === 0) continue
        const nx = cx + dx, ny = cy + dy
        if (nx < 0 || ny < 0 || nx >= cols || ny >= rows) continue
        const ni = idx(nx, ny)
        if (!passable[ni] || closed[ni]) continue
        // 不切角：斜走时两边正交的格子也得通
        if (dx !== 0 && dy !== 0) {
          if (!passable[cy * cols + nx] || !passable[ny * cols + cx]) continue
        }
        const step = (dx !== 0 && dy !== 0) ? Math.SQRT2 * cell : cell
        const tentative = gScore[ci] + step
        if (tentative < gScore[ni]) {
          cameFrom[ni] = ci
          gScore[ni] = tentative
          fScore[ni] = tentative + h(ni)
          // ⚠ f 变小时必须重新入堆
          open.push({ f: fScore[ni], i: ni })
        }
      }
    }
  }

  if (cameFrom[goal] === -1 && goal !== start) return []

  // 回溯格子序列 → 世界坐标折线
  const cells: number[] = []
  let cur = goal
  while (cur !== -1) { cells.push(cur); if (cur === start) break; cur = cameFrom[cur] }
  cells.reverse()

  const pts: Point[] = [{ x: from.x, y: from.y }]
  for (const ci of cells) {
    const cx = ci % cols, cy = (ci - cx) / cols
    const c = center(cx, cy)
    const last = pts[pts.length - 1]
    if (Math.hypot(c.x - last.x, c.y - last.y) > 0.01) pts.push(c)
  }
  pts.push({ x: to.x, y: to.y })
  return dropCollinear(pts)      // 去掉共线冗余点，见 9.3
}
```

> **性能提示**：大画布上一次寻路会分配约 10MB 的临时数组
> （gScore / fScore / cameFrom / closed 四份）。
> 场上有多只怪物就意味着多次寻路，几百 MB 的临时垃圾会让 GC 拖成周期性卡顿
> —— 表现为「走两步顿一下」，比单次算得慢更难忍受。
> 把这四个数组缓存起来复用（格子数变了才重新分配）。

### 9.3 折线后处理

**去掉共线的冗余点**（严格共线才删，拐弯点全部保留）：

```ts
function dropCollinear(pts: Point[]): Point[] {
  if (pts.length < 3) return pts
  const out = [pts[0]]
  for (let i = 1; i < pts.length - 1; i++) {
    const a = out[out.length - 1], b = pts[i], c = pts[i + 1]
    const cross = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x)
    if (Math.abs(cross) < 1e-6) continue   // 三点共线 → 删中点
    out.push(b)
  }
  out.push(pts[pts.length - 1])
  return out
}
```

> A* 每走一个格子中心就记一个点，一条绕墙的路线能到几百个点，
> 其中 98% 以上是同一直线上的中间点 —— 画出来毫无区别，
> 却让逐帧绘制多画几百个节点，也让下面的验证多跑几百次。

### 9.4 折线必须验证

**A* 只给粗略路线，窄道里按格子跳会穿墙。**
折线要**用第七章的 `tryMoveChar` 逐段推进**来验证：

```text
起点必须站得住（否则脱困规则会让判定失去意义）
对每一段 (a → b)：
    步数 = ceil(|b - a|)
    每步调用 tryMoveChar(incX, incY)
    走完后必须真的到达 b（距离 b 超过 1.5px 就算「被墙挡在半路」→ 走不通）
```

```ts
function verifyPath(regions: Region[], points: Point[], bw: number, bh: number): boolean {
  if (points.length < 2) return false
  if (!canStandAt(regions, points[0].x, points[0].y, bw, bh)) return false

  const state = { x: points[0].x, y: points[0].y, regions }
  for (let i = 0; i < points.length - 1; i++) {
    const a = points[i], b = points[i + 1]
    const dx = b.x - a.x, dy = b.y - a.y
    const steps = Math.max(1, Math.ceil(Math.hypot(dx, dy)))
    const incX = dx / steps, incY = dy / steps
    for (let s = 0; s < steps; s++) tryMoveChar(state as any, incX, incY)
    // 必须真的走到这一段的终点（不能被墙挡在半路）
    if (Math.hypot(state.x - b.x, state.y - b.y) > 1.5) return false
  }
  return true
}
```

因为验证用的是**角色移动本尊**，所以「寻路结果的可靠性 = 角色实际移动的可靠性」天然成立。

### 9.5 巡逻路线展开

把巡逻路径点展开成真正能走的折线：

```ts
function planPatrol(grid: NavGrid, points: Point[], loop: boolean): Point[][] {
  if (points.length < 2) return []

  const legsOf: { from: Point, to: Point }[] = []
  for (let i = 0; i < points.length - 1; i++) {
    legsOf.push({ from: points[i], to: points[i + 1] })
  }
  // 闭环：最后一点绕回第一点
  if (loop) legsOf.push({ from: points[points.length - 1], to: points[0] })

  return legsOf.map(l => {
    const p = findPath(grid, l.from, l.to)
    return p.length ? p : []      // 空数组 = 这一段走不通（被墙彻底隔开）
  })
}
```

每段路径点之间的折线由 A*（9.2）绕开墙。
